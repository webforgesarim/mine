Seven security basics every business website needs

Most hacked small websites were not targeted for who they are. They were found by automatic scanners looking for easy mistakes. Fix these seven and you are already harder to attack than most.

1. Use HTTPS everywhere

The padlock next to your address means traffic between the visitor and your site is encrypted. Free certificates are available, so there is no reason to skip it. Make sure the plain http address redirects to https.

2. Keep software updated

Your website platform, plugins and themes all get security fixes. Sites that run old versions are the easiest to break into. Turn on automatic updates where you can.

3. Back up automatically, away from the server

A backup stored on the same server disappears with the server. Keep a recent copy somewhere else, and try restoring it once so you know it works.

4. Turn on two-step login

Add a code from your phone to the admin panel, your hosting account, your domain registrar and your email. A stolen password alone is then not enough.

5. Use unique, long passwords

Reusing a password means one leak opens every account. A password manager makes unique passwords painless.

6. Give people only the access they need

Remove accounts of former staff and freelancers. Not everyone who edits content needs to be an administrator.

7. Know when your site goes down

A free uptime monitor can message you when something breaks, so you hear it before your customers do.

SQL injection explained in plain words

Many websites keep their data in a database and talk to it using a language called SQL. SQL injection happens when a site pastes what a visitor typed straight into a database question, and the visitor types something that changes the question.

The mistake

Imagine a login form. The code builds a query by gluing text together:

name = request.form["name"]
query = "SELECT * FROM users WHERE name = '" + name + "'"

If someone types a normal name, it works. But if they type ' OR 1=1 --, the query becomes:

SELECT * FROM users WHERE name = '' OR 1=1 --'

Because 1=1 is always true, the database returns every user. The -- turns the rest of the line into a comment. The visitor has rewritten your question.

The fix: parameterised queries

Send the query and the visitor’s text separately. The database then treats the text only as data, never as instructions:

cursor.execute("SELECT * FROM users WHERE name = %s", (name,))

Every serious database library supports this. If your code builds queries by joining strings, that is the first thing to change.

Extra layers

  • Give the website’s database account only the permissions it needs, never full admin rights.
  • Do not show raw database errors to visitors. They reveal how your tables are built.
  • Validate input, for example by checking that an age field really contains a number.

How to spot a phishing message in 10 seconds

Phishing is a message that pretends to be a bank, a courier, a boss or a friend so that you click a link or share a secret. Take ten seconds and run these five checks.

  1. Look at the real sender. The display name can say anything. Check the actual address, and watch for small spelling changes like a swapped letter.
  2. Notice the pressure. “Your account will be closed today” and “you have won a prize” are designed to make you act before you think.
  3. Check where the link really goes. On a computer, hover over it. On a phone, press and hold. If the address is not the company’s own site, do not open it.
  4. Be careful with attachments. Unexpected invoices, zip files and files ending in .exe are common ways to deliver malware.
  5. Never share codes. No genuine bank, courier or support agent will ask for the one-time code sent to your phone.

If you already clicked

  • Do not enter anything on the page. Close it.
  • If you did type a password, change it right away, and change it anywhere else you reused it.
  • Turn on two-step login for that account.
  • If money or a bank card is involved, contact your bank immediately using the number on your card.

When unsure, do not use the message. Open the company’s site or app yourself and check there.

Why a long password beats a clever one

“Joseph@123” looks strong because it has a capital, a symbol and numbers. Attackers know that pattern well, and guessing programs try it in the first few moments. What really protects you is length and randomness.

Why length wins

Every extra character multiplies the number of possible passwords. A longer password also makes a guessing attack take far longer, even if it uses only simple words, as long as the words are not predictable.

Use a passphrase

Pick four or more unrelated words at random, such as “lamp river orange stapler”. It is easy to remember and much harder to guess than a short, complicated password. Do not use a famous quote or a sentence about yourself.

Use a password manager

A manager creates a long random password for every site and remembers it for you. You only remember one strong master passphrase. This ends the habit of reusing passwords.

Add two-step login

Even a very good password can leak from a site you do not control. A second step means a leaked password alone is not enough.

How sites should store passwords

Well-built sites never store the password itself. They store a slow, salted hash made with a method such as bcrypt or Argon2, which makes each guess expensive for an attacker.
